# 临时会话、保存项目与缓存管理

GUI 新计算默认属于**未保存会话**。运行结果、敏感性/ROP、评分与图表先写入临时磁盘工作区，以避免全部驻留内存，并支持运行中查看与任务恢复。这里的“不保存”指不自动归档为项目，并不意味着完全禁止临时磁盘文件。关闭浏览器不会删除文件或停止后台计算。

2026-10-20 起，新批量计算仅长期保留各工况预测值、验证记录、条件/机理身份及入口/出口状态。不保留全部积分步或火焰场。完整历程在求解和点火判定期间仍可能临时写盘，完成后由最多两行状态文件替代；现有完整历程不自动批量修改。绘图加密工况各自的出口预测值仍保留，因此模拟曲线不会因删减历程而变成只有两个点。

需要完整计算域的 ROP、点火温度敏感性诊断会仅重建选中单点历程，检查重建预测值与保留结果一致，再进行分析，退出时删除临时历程（含失败退出）。PFR ROP 仍积分完整计算域，不能用两行状态替代。原生 PFR/JSR 敏感性本来就重新积分，可直接使用保存的端点与预测值；已有身份一致的分析结果仍可复用。精简状态的 ROP 位置选择仅有入口/出口，任意内部位置需完整单点历程。

## 保存和打开

在左侧展开“项目：保存 / 打开”，填写项目名称，按需选择：

- 模拟结果（绘图、评分与端点状态）；
- 当前载入的敏感性 / ROP 分析；
- 图表。

点击“保存项目”才会创建 `results/projects/<项目名称>/`。同名项目不会覆盖；后续更新需换名保存。无勾选内容时只保存配置。保存期间会阻止活动计算，以免复制未完整提交的数据。保存的是当前载入的批次和分析；要保存其他批次，应先载入对应结果。

保存过程会复制已引用的状态文件、全物种敏感性矩阵及工作机理，重写 JSON 中的依赖路径；机理 YAML 字节不变。复用旧批次或快照得到的状态文件也被复制，避免舍弃临时会话后项目失效。历史批次仍可能带有完整历程；保存历史批次不会悄悄删减其数据。保存失败时删除本次未完成副本，保留来源。同名覆盖及缺少依赖会明确报错。

“打开所选项目”载入已有结果，不重新计算。含模拟结果的项目可继续评分、绘图；只含分析的项目在“单工况分析”查看；只含图表的项目在“图表与导出”选择图表组查看。重新评分和绘图使用临时副本，不修改已保存项目。

当前项目保存目录的内部绝对路径基于本机工作区。跨机器移动整个项目目录时，不能假定所有绝对路径会自动重定位；原实验数据和配置中的原始机理路径也应同步配置。CSV 和 SVG 中可能保留来源路径作为溯源文本，数值依赖以 JSON/HDF5 为准。

## 文件位置

| 位置 | 用途 |
|---|---|
| `.cache/sessions/<会话标识>/` | GUI 模拟、快照、后处理临时文件 |
| `results/analysis/temporary-<会话标识>-.../` | 临时单工况分析，登记在对应 session.json 中 |
| `results/analysis-batches/temporary-.../` | 临时分析任务清单 |
| `results/analysis-comparisons/temporary-.../` | 临时分析比较图与导出 |
| `results/projects/<名称>/` | 用户明确保存的项目 |
| `.cache/ui-session.json` | 最近运行配置及临时会话恢复标识 |
| `results/` 原有批次 | 历史成果，保留不迁移、不自动删除 |

输入 XML、源机理、上传输入及已转换的工作机理仍为输入，不属于结果自动清理对象。CLI 的 `run <配置>` 显式指定输出目录，仍向该目录写入可恢复结果；本次修改 GUI 的默认归档行为，不改变已有脚本接口。

## 清理

左侧“缓存与内存管理”默认折叠，不持续扫描磁盘：

- 启动检查仅自动删除已失效的图片预览与过期下载临时文件；不删除数值历程。
- “检查缓存占用”后，可选图片预览、下载 ZIP 副本、开发与测试缓存进行清理；原始图表和计算结果保留。
- “释放当前载入结果的内存”卸载结果/预检查/分析索引，清除 Streamlit 数据缓存；之后需要时可重新载入。
- 检查临时会话后，可选择旧会话，确认后舍弃其模拟、分析和图表临时文件。当前会话需先通过“开始新的临时会话”切换；尚未保存的内容删除后不可恢复。

存在活动计算、分析或打包/测试任务时，磁盘清理会拒绝执行。当前仍载入或被其他结果引用的临时数值文件也受保护。清理前后均检查实际路径、文件是否变化以及链接，不递归删除项目以外位置。已保存项目和历史结果不在临时会话清理范围内。

默认不会因浏览器断开而自动舍弃未保存会话，避免运行中断和误删；用户可在确认保存后主动清理。
