# 敏感性 / ROP 自动缓存加载（2026-10-12）

此前缓存只在点击“分析选中工况”时查找，切换分析内容后仍展示上一份分析。部分 ROP 的物种和位置选项还参与敏感性缓存匹配，导致本应可复用的结果没有命中。

现在选择工况、机理及分析类型后自动检查已完成报告，显示“已有缓存 / 需新计算”数量，并载入对应结果。全部任务命中缓存时禁用计算按钮，可直接查看图表；只有未命中的部分才进入顺序计算队列。敏感性与 ROP 分为独立任务，既能组合此前各自的报告，也能复用旧联合报告中的相应部分。未命中时清除此前自动展示的其他类型结果，避免将旧图误当作当前选择。

敏感性忽略只影响 ROP 的物种和位置；ROP 忽略只影响敏感性的目标、反应选择、近零阈值和指定时刻。真正的机理、原始历程内容、敏感性目标和反应编号、数值设置、ROP 物种及位置仍严格匹配。JSR 的稳态敏感性收敛依赖目标，因此没有任意忽略敏感性 target_key。已保存的全物种矩阵仍可在下方展示物种选择器中查看其他物种，无需再次积分。

带全物种矩阵的缓存要求 HDF5 存在且 case_id / mechanism_sha256 对应当前请求。被缓存检查拒绝的报告不会因为目录名相同而被当作完成结果，也不会被新计算覆盖；新尝试独立保存。

PFR 保存全物种矩阵时可以复用此前其他目标物种的敏感性：积分终点由停留时间确定，与展示目标无关；只读取新物种对应矩阵行。网页中发现 Set4 / 1073 K 原报告目标为 CH4，而当前选择为 CH3NH2，该差异此前会误触发重算。现要求矩阵身份正确且包含请求物种才复用。JSR 不做这种跨目标自动复用，因为其敏感性稳态收敛检查依赖目标。

数值计算代码及 numeric_signature 来源没有更改，旧报告的审计证书没有重新签发。回归测试覆盖缓存、布局、任务队列及图表，并用真实 PFR 工况已保存的敏感性 / ROP 配对执行 Streamlit AppTest：敏感性 → ROP → 敏感性 → 二者同时显示；全过程禁止创建计算进程、检查报告原始字节不变。测试代码 tests/test_analysis_auto_loading.py。新增测试验证 PFR 可读取其他物种，但 JSR 跨目标仍不能自动视为已通过收敛验证。
