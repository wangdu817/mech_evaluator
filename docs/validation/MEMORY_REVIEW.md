# 内存复审与 XML 覆盖选择（2026-10-10）

## 当前证据与边界

`results/streamlit-saved-species-test.log` 明确记录了 MemoryError，调用链为完成后的单工况分析页面 → Streamlit 图片预览 → PIL 图片转换。无法从该日志重建崩溃当时各计算进程的内存峰值，也不能据此断定 Cantera 没有其他内存风险。

本轮开始的只读快照显示无活动项目运行锁、无仍在运行的计算/网页服务。当前 UI 批次记录 3812 工况、425 success、3369 solver_failed、18 invalid_input；大量失败的具体原因是此前的进程入口序列化错误，不能解释为化学机理预测失败。这些原记录保留，没有自动重新运行全部任务。

## 修复

- 完成后的敏感性页面停止自动轮询。两秒轮询只用于活动任务的轻量进度；完成后转为普通结果页面。
- 网页预览最长边 1400 像素，主后处理一次显示一张图；不修改已有 300 dpi 导出图。拒绝解码超过 2500 万像素的源图片，新图导出也设像素上限。
- 下载包仅点击时生成，ZIP 流式写到磁盘。Streamlit 最终仍会将下载保留在内存，因此源文件总量超过 64 MiB 时要求从结果目录读取，避免假称完全流式下载。
- 文件哈希按 1 MiB 分块读取，结果与 SHA256 全文件算法完全一致。
- 保留已有历程分块落盘和进程池回收机制。增加系统物理内存及 Windows 提交余量保护，默认保留 max(2 GiB, 物理内存的 10%)；计算 worker 默认上限 2 GiB。
- 计算监督进程每 0.25 秒检查其所属池的 worker，避免只能等原生求解器回到 Python 后才能取消。紧急停止仅作用于该池，记录 cancelled 和具体原因，已提交缓存保留。低内存停止后不立即进行昂贵绘图/评分导出。
- 敏感性仍使用一次 Cantera 默认容差求解，没有重新增加容差复核，也未修改反应参数。

## XML 分类

绘图页新增“按 XML 模拟覆盖情况筛选”：全部、有模拟曲线、全部完成、部分完成、未运行、计算失败或不可用。

选项直接显示分类及各机理“可用原始测量预测数 / 原始测量总数”。计算按当前载入结果与当前选择的机理进行，不能把其他机理的成功结果算作当前机理完成。原始测量身份为 series + 原始点编号，保留零浓度、多仪器和重复测量；加密点另列，不提升原始完成率。success 必须通过原有数值验证且目标预测有效才可用。没有预测的 XML 仍可查看实验点。

覆盖明细在评分页和绘图页可查看。历史批次目录也保留仅失败的批次，方便定位不可用状态。
